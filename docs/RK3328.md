# Running on the RK3328 HMI board

The same application runs on the desk and on the scooter's panel: a Rockchip
RK3328 board with a 7-inch HDMI touchscreen, Yocto (Poky) Linux, Weston on
DRM/KMS and Qt 6.2.

## What board mode changes

`--board` (or `EAGLE_BOARD=1`, set by the service):

- full screen, frameless, on Wayland;
- the software scene graph, because the RK3328's Mali/EGL stack is unreliable
  with Qt Quick; shader effects are switched off with it;
- the on-screen keyboard (Qt Virtual Keyboard) for Wi-Fi passwords and dialling;
- the UI, laid out on a 1920 × 1080 canvas, scales to the panel (1024 × 600 or
  1280 × 720) keeping its proportions.

Bluetooth uses the board's BlueZ adapter through Qt Bluetooth, Wi-Fi uses
NetworkManager through `nmcli`, and vehicle data comes from `can0`
([CAN.md](CAN.md)). Without a CAN interface the service falls back to the
built-in ride simulator, so a bare board still shows a working dashboard.

## Build and deploy

```sh
SDK_ENV=/opt/poky/4.0.27/environment-setup-armv8a-poky-linux deploy/rk3328/build.sh
BOARD=root@10.42.0.132 deploy/rk3328/deploy.sh
```

`deploy.sh` copies the binary to `/opt/eagle/bin`, installs
`eagle-dashboard.service` (after `weston.service`), brings `can0` up at
500 kbit/s and starts the dashboard. Logs: `journalctl -u eagle-dashboard -f`.

## Display bring-up

If the panel reports no usable EDID modes (seen with the Waveshare 7-inch LCD),
Linux falls back to a wrong resolution. Fix the mode at the DRM/kernel level
first (`modetest -M rockchip`, `/sys/class/drm/card0-HDMI-A-1/modes` should list
1024x600), then start the service.

## Known limits

- Built and run with Qt 6.8 on macOS; the Qt 6.2 board build follows the same
  code paths (no Qt 6.4+ APIs, no QtQuick.Effects) but has not been run on the
  board yet.
- Bluetooth needs an HCI controller exposed to BlueZ; some RK3328 images have none.
- Calls and media from the phone are simulated until the HFP and AVRCP profiles
  (oFono, BlueZ MediaPlayer1) are wired to `PhoneService`.
